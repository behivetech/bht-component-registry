Template: the class-name helper is shared, not copied into every package. Components list `@behivetech/bht-class-names` as a `workspace:^` dependency (the generator and the example packages do) and the shared tsup config bundles nothing, so each build imports one copy; `pnpm release` turns `workspace:^` into a normal range. The template publishes the helper to GitHub Packages for now. `create` and `update` keep your copy of `packages/class-names` workspace-only (`"private": true`, no `publishConfig`), so it links and is never published from your repo. The root `.npmrc` is back, pointing the `@behivetech` scope at GitHub Packages (temporary, until npm publishing returns): installing needs a token with `read:packages`, which goes in your user-level `~/.npmrc` as `//npm.pkg.github.com/:_authToken=${NODE_AUTH_TOKEN}` (pnpm 11 ignores a credential that expands an environment variable in a project `.npmrc`), and in CI the repository secret `PACKAGES_READ_TOKEN`. The CI lockfile check now allows npmjs and GitHub Packages and refuses any other registry. The Dockerfile takes the token as the build secret `npm_token`. Guide: Getting started, Adopting, Publishing, Deploy, Testing and CI, FAQ, Env. Existing registries: add `"@behivetech/bht-class-names": "workspace:^"` to each component's `dependencies` (and drop `@bht-component-registry/class-names` from `devDependencies`), change the import to `@behivetech/bht-class-names`, then `update`.
